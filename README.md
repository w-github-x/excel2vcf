# Excel 关键词 & 通讯录生成器

一个**纯本地**的单文件 HTML 工具：导入 Excel → 自由组合列成字段 → 生成 vcf 通讯录 / 关键词列表。
vcf 输出格式与手机（安卓）导出的 VCF 2.1 完全一致，可原路导回手机通讯录。

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 主程序，**双击即可用**，不联网、不上传 |
| `xlsx.full.min.js` | SheetJS 解析库（工具离线可用；同目录找不到时从 CDN 兜底） |
| `vcf校验器.py` | 可选：生成 vcf 后用它校验格式是否符合 vCard 2.1 |
| `_t/test_vcf.js` | 可选：Node 单测（含"与手机样例逐属性比对"的金样测试） |

> `index.html` 必须和 `xlsx.full.min.js` 放在**同一目录**。

## 用法

### 通讯录 vcf

1. 上传 `.xlsx / .xls / .csv`
2. 选工作表 + 填「表头所在行」（数据从下一行开始读）
3. 定义字段：一个字段 = 名称 + 参与列（可多列）+ 分隔符
   - 例：字段名「姓名」，参与列选 `A` 和 `B`，分隔符留空 → 得到「张三丰」
4. 把字段映射到通讯录属性，可加前后缀
5. 「生成并下载 vcf」

**长行折行开关（重要）**：界面里有个「长行折行」复选框，**默认不勾选 = 不折行**——和你手机自己导出的行为一样（它导出 91 字节也是原样写的，不折）。部分国产 ROM 的导入器对折行支持有坑，导入失败时先保持不勾选。少数严格导入器（Outlook 等）才需要勾选（按 vCard 规范折成 ≤75 字节）。

**可映射的属性（与手机导出格式一一对应）**

| 分组 | 属性 | 说明 |
|---|---|---|
| 基本信息 | 姓名（FN） | 自动生成 `N`（首字为姓）+ `FN`（全名） |
| | 姓氏拼音 | `X-PHONETIC-LAST-NAME:` 裸写 |
| | 昵称 | `X-ANDROID-CUSTOM` 安卓昵称（16 段结构） |
| | 生日 | `BDAY:` 支持完整日期或只有月日 |
| 电话/邮箱 | 手机 / 住宅电话 / 单位电话 | `TEL;CELL` / `TEL;HOME` / `TEL;WORK` 裸写 |
| | 邮箱·住宅 / 单位 | `EMAIL;HOME` / `EMAIL;WORK` 裸写 |
| 地址 | 住宅地址 / 单位地址 | `ADR;HOME` / `ADR;WORK`，7 段结构，整句地址进街道段 |
| 单位/备注 | 公司 / 职位 / 备注 | `ORG` / `TITLE` / `NOTE`（CHARSET+QP） |
| 社交/其他 | QQ / 微信 | `X-QQ` / `X-WECHAT` 裸写 |
| | 纪念日 | `X-ANDROID-CUSTOM` 安卓纪念日，**标签取自字段名** |

要点：

- 同一属性可映射**多个字段**：两个手机号、多个单位地址、多个纪念日（字段名即标签，如「结婚纪念日」「（自定义）」）
- 日期列支持 `2026-10-25` / `10-25` / `10月25日`，自动规范成 `BDAY:--10-25` 这种格式；无法识别的日期跳过
- 没有姓名映射时，显示名自动兜底为第一个可用值（手机号等），与手机导入行为一致
- 学号/班级等手机不显示的信息，映射到「备注」

### 关键词列表

同一份字段，切换到「关键词列表」标签页：

- 模板里用 `{字段名}` 占位：`{姓名}在{城市}读书`
- 支持多变量：`{城市}的{品类}`
- 支持关键词库笛卡尔积：填关键词库（每行一条），模板里用 `{关键词}` 指定插入位置
- 任一占位符为空 → **整条跳过**（计入「跳过空值」计数）
- 结果去重，总量上限 **500 条**
- 导出：复制 / txt / csv

## 关键规则

- **列上限 20 列**：只读取表格前 20 列
- **结果上限 500 条**：vcf 卡片数与关键词数都受此限制，超出截断并提示
- **表头行决定列名**：该行下方的所有行都是数据行；表头为空的列用列标（A、B、C…）代替
- **两种输出的空值规则不同**：
  - 关键词：任一占位符为空 → 跳过整条
  - vcf：某个字段为空 → 跳过该字段（所以可能出现只有手机号、没有姓名的卡片）
- **vcf 不带 BOM**：BOM 会让部分手机解析器把第一个属性解析失败

## 生成的 vcf 遵循的规范

vCard 2.1，输出形态与该手机导出格式逐属性一致，已通过严格校验器 + 金样测试（对照真实手机导出样例解码比对）：

- 纯 ASCII 输出，中文一律 QUOTED-PRINTABLE 编码；可打印 ASCII（分号/逗号/@ 等）除 `=` 外原样直通，与手机导出一致
- CRLF 换行；**默认不折行**（与手机导出行为一致：长行原样写）；勾选「长行折行」后每行 ≤ 75 字节，折行点不落在 `=XX` 三元组中间
- 折行为纯 RFC 2425 折行（续行以空格开头，不放 QP 软换行 `=`），"先合并再解码"与"逐行解码"的解析器都不会错
- `N:姓;名;;;`（首字为姓，5 段）、`FN:全名`
- `ADR;HOME:;;地址;;;;`（7 段：邮政信箱;扩展;街道;城市;省;邮编;国家）
- `X-ANDROID-CUSTOM` 值补齐到 16 段：昵称 `mime;昵称;1;…`、纪念日 `mime;日期;0;标签;…`
- 姓名中的 `;` `,` `\` 按 vCard 规则转义；昵称/纪念日标签/地址里的 `;` 替换为全角分号，避免撑破字段结构

## 已知限制

- `X-PHONETIC-LAST-NAME` / `X-QQ` / `X-WECHAT` 等裸写属性不含中文；万一填了非 ASCII 会自动加 `CHARSET+QP` 参数
- 微信**没有批量导入 vcf 的入口**，需先导入系统通讯录再走同步
- 单批建议 ≤ 2000 条（500 是本工具的硬上限，手机端还会更严格）

## 校验生成的 vcf

```bash
python vcf校验器.py 通讯录.vcf
```

检查：无 BOM / 纯 ASCII / CRLF / 行长 ≤75 / 属性名合法 / N 5段 / ADR 7段 /
X-ANDROID-CUSTOM 16 段 / FN 非空 / TEL 格式，全 PASS 才算格式正确。
